# Структура документов ОСББ

Модуль `osbb_document_storage.py` — единое описание разделов и допустимых
подкаталогов. Корень задаётся в `config.paths.OSBB_DOCUMENTS_ROOT` через
переменную окружения `OSBB_DOCUMENTS_ROOT`, отдельно для каждой машины.
С 2026-09-27 значение по умолчанию: `OneDrive/OSBB/Docs`.
На Mac используется `~/OneDrive` (существующая ссылка на CloudStorage),
на Windows — переменная `OneDrive`, при её отсутствии `~/OneDrive`.
Явный `OSBB_DOCUMENTS_ROOT` имеет приоритет, в том числе при облачном развёртывании.
Техническая документация проекта остаётся в `docs`; оригиналы ОСББ здесь
не копируются и не перемещаются автоматически.

Примеры конфигурации (пути условные; подставьте реальный подключённый том):

```zsh
export OSBB_DOCUMENTS_ROOT='/Volumes/OSBB_Archive/OSBB_Documents'
```

```powershell
$env:OSBB_DOCUMENTS_ROOT = 'D:\OSBB_Documents'
```

В облачном развёртывании указывается абсолютный путь подключённого
постоянного хранилища, например `/mnt/osbb-documents`. Для OneDrive —
фактическая синхронизируемая папка; пути OneDrive на Mac/Windows не угадываются.
Это файловый адаптер, не клиент OneDrive/S3. Для объектного облака нужен
отдельный адаптер. Облачная синхронизация не заменяет резервные копии.

Корень должен быть заранее подготовлен и доступен. Если том отключён,
модуль сообщает об ошибке и не создаёт случайную локальную папку на SSD.
Импорт config и модуля ничего не создаёт.

Раздел `announcements` — `09_Announcements/Print`, объявления для печати
и расклейки. 2026-09-27 восемь файлов из корня OneDrive/OSBB перенесены
туда без изменения содержимого; карта переноса с SHA-256 хранится в
`Docs/initial_announcements_move_20260927.json`. Перенесены также два Excel
и PNG, сопровождавшие объявления. Подтверждение облачной синхронизации
этим локальным переносом не производится.

## Приём файлов (2026-09-27)

Консоль: страница «📥 Документы ОСББ — Входящие», выбор нескольких
файлов или перетаскивание, затем «Сохранить во входящих». Пока это локальный
однопользовательский режим; исполнитель — текущий пользователь Mac.
Бот: «📥 Передать документ ОСББ» в админском меню либо отправка/пересылка
файла или фото в личный чат. Приём разрешён действующим администраторам
или пользователям с `osbb_documents.CREATE`; OSBB_READ_ONLY сам по себе
этого права не даёт. Групповые чаты не принимаются.

Общий модуль `document_intake_core.py` ограничивает файл 20 МБ и перечнем
документных/графических расширений; программы и архивы не принимаются.
Файлы не исполняются и не анализируются, антивирус пока не подключён.
Уникальное внутреннее имя предотвращает перезапись; исходное имя сохраняется
в `osbb_documents`. SHA-256 выявляет точные дубли, повторные поступления
записываются в `osbb_document_receipts`. Записи аудируются. Поля паспорта:
ID, код хранилища, относительный путь, исходное имя, SHA-256, размер,
статус INBOX, исполнитель и время. Классификация, категории и анализ ИИ —
следующий этап. Успех локального сохранения не подтверждает завершение
синхронизации OneDrive. Старые файлы объявлений автоматически не индексируются.

Показать структуру:

```zsh
.venv/bin/python osbb_document_storage.py
```

Проверить план каталога закупки без записи:

```zsh
.venv/bin/python osbb_document_storage.py --section procurement --year 2026 --entity 0001 --folder Invoice
```

Создать только этот каталог и необходимых родителей:

```zsh
.venv/bin/python osbb_document_storage.py --section procurement --year 2026 --entity 0001 --folder Invoice --apply
```

На Windows используйте `.venv\Scripts\python.exe` с теми же аргументами.
Год не подставляется скрыто: для finance/procurement он задаётся явно.
Остальные годовые каталоги не создаются заранее.

## Ссылки

`document_reference('procurement', year=2026, entity='0001', folder='Invoice',
filename='invoice.pdf')` возвращает:

```json
{"storage":"OSBB_DOCUMENTS","path":"04_Procurement/2026/PO_0001/Invoice/invoice.pdf"}
```

`resolve_reference` переводит её в путь для текущей машины и проверяет,
что путь не выходит за корень, включая символические ссылки. Перенос
хранилища требует изменения config, а не каждой ссылки. Новые интерфейсы
должны использовать этот API. Старые свободные ссылки договоров пока не
мигрированы; индекс документов, версии и загрузка файлов — следующий этап.
