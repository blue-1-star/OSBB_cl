# Контроль безопасности Telegram-бота OSBB

`bot_security_watch.py` только читает публичные настройки бота. Он **не меняет**
профиль, вебхук, токен и сообщения. Токен импортируется из
`/Secret/Soft/telegram_osbb.py` и не записывается в журнал.

Проверяются ID и username бота, имя, About, Description, аватар, команды,
локализованные тексты (`uk`, `ru`, `en`) и отсутствие вебхука. Любая новая
внешняя ссылка в About/Description вызывает тревогу даже без эталона.
Эталон после восстановления профиля сохранён локально в
`data/security/bot_profile_baseline.json`; Git его не публикует. При
легитимном изменении профиля нужно сначала проверить его в BotFather, затем
обновить эталон командой `enroll` и подтвердить действие словом
`ПОДТВЕРЖДАЮ`.

Из корня проекта:

```sh
.venv/bin/python bot_security_watch.py check
.venv/bin/python bot_security_watch.py show
.venv/bin/python bot_security_watch.py enroll
.venv/bin/python bot_security_watch.py watch
```

При обычном запуске `osbb-bot` проверка выполняется сразу и далее каждые
пять минут. Отдельный `watch` нужен, только если требуется проверка при
остановленном боте; он запускается вручную, без автозапуска службы.
Telegram-ошибки `Conflict` и `InvalidToken` также вызывают тревогу.

Тревога появляется в терминале, журнале `data/logs/bot_security.log` и,
если macOS разрешает уведомления из Terminal, системным уведомлением.
Это локальные каналы: при выключенном Mac или неработающем отдельном
`watch` контроль остановленного бота не выполняется. На событие нужно
реагировать вручную: проверить BotFather и сеансы Telegram, остановить
лишние экземпляры, при необходимости отозвать токен, обновить Secret и
восстановить публичные тексты. Нельзя автоматически утверждать новый
эталон после тревоги.

Журнал и эталон не содержат токен. Однако журнал может содержать публичные
тексты/ссылки, появившиеся при подмене профиля; его не следует публиковать.
