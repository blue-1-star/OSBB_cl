# Контроль безопасности Telegram-бота OSBB

`bot_security_watch.py` только читает публичные настройки бота. Он **не меняет**
профиль, вебхук, токен и сообщения. Токен импортируется из
`/Secret/Soft/telegram_osbb.py` и не записывается в журнал.

Проверяются ID и username бота, имя, About, Description, аватар, команды,
локализованные тексты (`uk`, `ru`, `en`) и отсутствие вебхука. Любая новая
внешняя ссылка в About/Description вызывает тревогу даже без эталона.
Эталон после восстановления профиля сохранён локально в
`data/security/bot_profile_baseline.json`; Git его не публикует. При
легитимном изменении профиля нужно сначала проверить его в BotFather, затем
обновить эталон командой `enroll` и подтвердить действие словом
`ПОДТВЕРЖДАЮ`.

Из корня проекта:

```sh
.venv/bin/python bot_security_watch.py check
.venv/bin/python bot_security_watch.py self-test
.venv/bin/python bot_security_watch.py show
.venv/bin/python bot_security_watch.py enroll
.venv/bin/python bot_security_watch.py watch
```

При обычном запуске `osbb-bot` проверка выполняется сразу и далее каждые
пять минут. Отдельный `watch` нужен, только если требуется проверка при
остановленном боте; он запускается вручную, без автозапуска службы.
Telegram-ошибки `Conflict` и `InvalidToken` также вызывают тревогу.

Главное место просмотра — **админ-консоль → «Безопасность Telegram-бота»**
(кнопка на рабочем столе). Там видны последнее состояние, время проверки,
настоящие и тестовые тревоги; есть кнопки «Проверить сейчас» и «Испытать
тревогу». Тест показывает красное сообщение прямо на странице и не меняет
Telegram. Запущенный бот после первой проверки печатает результат в своём
терминале. Тест, выполненный отдельной командой, пишет в терминал **этой
команды**, а не в уже открытое окно бота.

Тревога появляется в терминале, админ-консоли, журнале
`data/logs/bot_security.log` и, если macOS разрешает уведомления из
Terminal, системным уведомлением. Уведомление macOS — дополнительный,
не гарантированный канал; в админ-консоли тест его пытается отправить только
при выбранной опции.
Журнал автоматически очищается при каждой новой записи: остаются две
последние штатные проверки **за сегодня**, до двух сегодняшних тестовых
тревог и не более 50 остальных событий (настоящие тревоги, восстановление,
изменение эталона). Штатные проверки и тесты прошлых дней удаляются; настоящие
тревоги не удаляются по дате. Чтобы применить эти правила к уже существующему
журналу без новой проверки Telegram, выполните
`.venv/bin/python bot_security_watch.py prune`.
Это локальные каналы: при выключенном Mac или неработающем отдельном
`watch` контроль остановленного бота не выполняется. На событие нужно
реагировать вручную: проверить BotFather и сеансы Telegram, остановить
лишние экземпляры, при необходимости отозвать токен, обновить Secret и
восстановить публичные тексты. Нельзя автоматически утверждать новый
эталон после тревоги.

Для безопасного испытания сначала выполните `check`: результат должен быть
без отклонений. Затем выполните `self-test`. Эта команда **не обращается к
Telegram и ничего там не меняет**: она моделирует чужое имя и ссылку в
памяти, выводит тревогу, пробует показать уведомление macOS и добавляет в
журнал запись с явным типом `SELF_TEST_ALERT`. После этого повторите
`check`: он должен снова показать нормальный профиль. Для проверки
периодического режима можно вручную запустить `watch` и остановить его
`Ctrl+C`; портить настоящий профиль или отзывать токен ради теста не нужно.

Журнал и эталон не содержат токен. Однако журнал может содержать публичные
тексты/ссылки, появившиеся при подмене профиля; его не следует публиковать.
