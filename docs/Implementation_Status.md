# Фактическое состояние проекта OSBB

**Статус:** предварительная инвентаризация 0.1  
**Основание:** доступная документация и найденные фрагменты кода.

## Правила оценки

- **Есть** — обнаружен работающий код или подробно описанная реализация.
- **Частично** — механизм существует, но не закрывает целевой сценарий полностью.
- **Запланировано** — решение принято, реализация не подтверждена.
- **Не подтверждено** — в доступных материалах реализация не найдена.

| Документация | Частично | Architecture, ADR, Roadmap, Log, Daily, Chronicle | До этого пакета не было общего ТЗ и матрицы |

## Сильные стороны

- Проект развивается из реальных эксплуатационных случаев.
- Уже существует значительная модель данных.
- Выделены Core_New, Finance Core, Presentation Layer, Development Infrastructure и Surgical Delete.
- Неполные данные, неизвестное назначение денег и ошибки рассматриваются как штатные сценарии.

## Главные ограничения

1. Нет подтверждённого единого цикла `тариф → начисление → поступление → распределение → баланс → отчёт`.
2. Часть бизнес-правил находится в UI и SQL.
3. Legacy и новые модели сосуществуют.
4. Состояние проекта до сих пор измерялось фрагментарно.

## Ближайшее рабочее ядро

```text
квартира / автомобиль
→ Telegram-кассир
→ услуга и период
→ сумма
→ cashier receipt
→ payment
→ cashbox operation
→ результат
```

Этот контур уже способен регистрировать реальные операции, но ещё должен быть встроен в полноценную модель тарифов, распределений, балансов и аудита.

## Ограничение достоверности

Для версии 1.0 нужна автоматическая инвентаризация полного репозитория: модулей, таблиц, Telegram-команд, точек записи, отчётов, миграций и тестов.
